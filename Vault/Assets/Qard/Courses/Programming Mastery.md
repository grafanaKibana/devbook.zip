C# establishes language semantics; .NET explains execution and concurrent work; ASP.NET applies them to request processing. Other currently contains WebAssembly.

The course has one starting point: the **Intro** of C#. C#, .NET and ASP.NET each start with an **Intro** objective for their hub note, and every other objective in the group opens only after it.

- **C#:** the Intro opens **Types**, **Exception Handling** and **Namespaces**. Types opens classes, then structs, then records and pattern matching; strings; methods; and generics, then delegates and events. Exception Handling opens foreach.
- **.NET** opens after **Exception Handling**. Its Intro opens two branches. Runtime: the runtime, the CLR, then garbage collection and memory leaks, reflection and .NET Standard. Concurrency: concurrency and parallelism, tasks, async/await, then the thread pool, cancellation and channels, and locking, which opens deadlocks, semaphores, mutexes and parallelism.
- **ASP.NET** opens after **Async Await**. Its Intro opens dependency injection and middlewares; middlewares open authentication (then authorization) and CORS; filters need both middlewares and dependency injection.
- **Other:** WebAssembly opens from the course Intro.

The recurring trap in C# is treating reassignment of a variable as a change to the shared object. **Types** is solid only when that distinction holds for a struct, a class instance and a reference held in a field.

Related material in other courses: HTTP (Networks), JWT and authorization models (Security), dependency injection as a pattern (Software Architecture), OOP and event-driven design (Software Design).

Existing assessment states, due dates and evidence stay with their objectives.
