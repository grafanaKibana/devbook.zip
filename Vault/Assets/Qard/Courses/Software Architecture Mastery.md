The course has one starting point: the **Intro** of Application Architecture. Every group starts with an **Intro** objective for its folder's hub note, and every other objective in the group opens only after it. Programming and Software Design provide the language and object-model foundations.

The route is **Application Architecture → System Architecture → Architectural Patterns → Design Patterns**, and from System Architecture **Resilience Patterns → Distributed Systems**. Application Architecture sets responsibility and dependency boundaries inside one application; System Architecture compares one deployment with network-separated services and event-driven coordination.

Architectural Patterns runs from dependency injection and command-query separation through Repository and Unit of Work to domain modeling, CQRS and event sourcing. Design Patterns opens with its Intro, then three branches, each behind its own hub objective: **Creational**, **Structural** and **Behavioral**. Each branch is one line from the easiest and most used pattern to the hardest; GRASP closes the group after all three. Resilience begins with idempotent effects before retries, circuit breakers and rate limiting. Distributed Systems ends with worked system-design scenarios after its correctness, messaging, scaling and availability topics.

Learn history remains attached to each objective's stable ID. Teaching and checks own assessment states, due dates and evidence; source-note completion alone does not establish mastery. This internal record maintains explicit source links outside Home. Start lessons and checks from its objectives; folder-based Update objectives does not map this course record.
