Application Architecture establishes responsibility and dependency boundaries inside one application. System Architecture then compares one deployment with network-separated services and event-driven coordination. These are the starting points for the course; Programming and Software Design provide the language and object-model foundations.

The recommended route is **Application Architecture → System Architecture → Architectural Patterns**, followed by the **Design Patterns** branch for object-level design and **Resilience Patterns → Distributed Systems** for reliable networked services. Group order is a study guide. The Needs column names direct knowledge dependencies; within Design Patterns it also enforces the chosen study sequence for each branch.

Within each group, the table runs from foundations to more specialized decisions. Architectural Patterns starts with dependency injection, command-query separation and domain modeling before persistence boundaries, CQRS and event sourcing. Design Patterns begins with Design pattern fundamentals, then splits into three independent branches: Creational, Structural and Behavioral. Each branch runs from easier to harder patterns, and GRASP responsibility assignment follows completion of all three branches. Resilience begins with idempotent effects before retries, circuit breakers and rate limiting. Distributed Systems ends with worked system-design scenarios after its correctness, messaging, scaling and availability topics.

Learn history remains attached to each objective's stable ID. Teaching and checks own assessment states, due dates and evidence; source-note completion alone does not establish mastery. This internal record maintains explicit source links outside Home. Start lessons and checks from its objectives; folder-based Update objectives does not map this course record.
